# 本地 Web 完整闭环执行计划

版本：执行计划 v1；日期：2026-10-15（America/Los_Angeles）。用户已确认本地网页先行，要求将执行交给另一个 Agent，并把结果带回本聊天审阅。当前尚无应用代码，本文件定义这次开发任务的范围与完成标准。

执行提示词见 [CODEX_HANDOFF.md](../CODEX_HANDOFF.md)，交付报告格式见 [EXECUTION_REPORT_TEMPLATE.md](../EXECUTION_REPORT_TEMPLATE.md)。[整体设计](WORKBENCH_DESIGN.md)描述长期方案，本计划决定本次实施优先级；用户后续指令优先。

## 1. 本次交付目标

交付一个可在本机浏览器使用的工作台，完成下面的真实闭环：

`用户输入 Goal → Windows Sol 规划 → Python 冻结任务并准入 → WSL Codex / DeepSeek 执行 → Python 收集证据 → Sol 验收 → Python 完成、修复或暂停 → 浏览器查看结果、用量和证据`。

同时用确定性的模拟场景验证失败、重规划、预算停止、重复请求和重启恢复。真实模型路径与模拟路径共用业务控制器，模式在界面、数据库和报告中明确区分。

本次包含最小可用的会话、Goal、证据、预算、Wiki/Markdown 导入、Skill 会话选择与四种轻量工作流。完整 Profile 编辑、第三方 Skill 商店、Deep Optimize 多候选评估、桌面壳、多 Worker 并行、SSH/CI、FastCtx 性能优化后续再实施，不以它们作为首个闭环前提。

这些是落实用户任务的实现默认值，并非其余 D02–D14 均已逐项确认。兼容性或现有代码要求调整时，由执行 Agent 采用最小可逆方案，写明理由与影响，不为常规实现细节反复求确认。

## 3. 执行方式

用户将[交接提示词](../CODEX_HANDOFF.md)交给一个能够访问本目录并运行 Windows/WSL 工具的 Agent。执行 Agent 连续完成 E0–E7，按依赖推进；本聊天不代为启动 Agent。

先检查已有代码、用户修改与 Git 边界。没有 Git 时可用文件清单和哈希追踪，不把初始化仓库作为阻碍。项目依赖放项目环境并锁定版本，启动命令在 README 写清。保持用户现有全局模型配置、登录状态与原始资料。

遇到缺失认证、预算、WSL 或运行时能力时，尽早集中报告具体缺口，并继续能独立完成的代码、模拟演示与测试。不得用模拟 PASS 冒充真实闭环；外部依赖确实无法完成时，最终交付可运行部分及准确阻塞状态。

## 4. E0：环境与协议验证

调查 Python、Node/包管理器、Git、Windows Codex、WSL 发行版与其中 Codex 的实际版本；确认原生执行文件路径、项目路径映射、可用模型/推理档位及认证是否就绪，不读取或输出凭据内容。

核对固定版本的官方 App Server 文档和实际协议：初始化、Thread 新建/续接、Turn、事件、用量和取消。使用最小试验确认 Windows Sol 与 WSL DeepSeek 各自可用；Skill 发现与隔离以实际结果记录。

输出 `docs/reports/ENVIRONMENT_REPORT.md`：每项 PASS/FAIL/BLOCKED/NOT_RUN、实际版本、证据位置和所需用户输入。真实调用需要现有有效认证与用户设置的测试预算；没有数额时实现配置入口，保留待执行集成验收，不能自行把示例数值视为消费授权。

通过条件：能力表来自实测或明确标注的文档依据。DeepSeek 接入失败时不静默更换执行模型；给出证据并保留可独立开发的 Adapter 边界。

## 5. E1：项目骨架与浏览器入口

建立 `backend/`、`ui/`、必要的配置、依赖锁定和本地启动脚本。提供后端健康检查、页面入口和清楚的错误提示；开发启动与构建后启动分别说明。

本地 API 默认回环监听，具备必要的本地认证及来源检查。前端调用统一 API，不直接启动 CLI 或读写状态库。生产方式由后端提供构建后的静态页面，不要求用户常驻 Vite 开发服务器。

通过条件：按 README 可启动并打开浏览器页面，页面可识别服务可用状态；停止服务时只处理本应用拥有的进程。

## 6. E2：契约、持久化与预算先行

实现 Workspace、Session、Goal/标准/计划版本、Decision、Task、Run、Result、Evidence、Review、Usage 和 Event 的最少对象。新实现统一 schema 版本类型；历史模拟示例保持原样，不把它们直接当已冻结协议。

SQLite 由 Windows Python 单写；大文件留在本地证据目录。状态变更和持久事件同事务提交。所有启动入口复用权限/状态/预算准入，支持幂等键、revision 和单写入槽。

先实现累计计量、未结算预留、100% 停止锁、明确恢复与重启保留锁，再开放真实自动执行。缺失用量不作为零；缓存/推理细分不重复相加。复核额度默认未启用。

提供确定性 Fake/Replay Adapter，重放一次失败→重规划→修复→验收，并验证去重、迟到事件和恢复。Fake 只替换外部运行时，不另写一条绕过预算的演示闭环。

通过条件：无模型账户也能复现业务不变量；模拟记录全部有 `mode=simulation` 或等价明确标记。

## 7. E3：Windows / WSL 原生接入与证据

实现两个精简 Codex Adapter，支持创建/续接、提交、输出标准化、用量、中断和状态查询。角色、环境、Provider、模型、Session、Thread、Run 和 Turn 分别保存。

Windows/WSL 使用独立原生配置和会话目录；必要的 WSL 辅助程序只转发或清理，不调度 Goal。运行时进程归属可核实，中断先走原生协议，超时后才清理本应用拥有的进程树，不能终止整个 WSL 发行版。

通过允许列表构造持久事件和 UI 输出，过滤原始推理及凭据，普通日志不保存完整协议原文。Evidence Collector 保存命令/退出码、测试与构建报告、Diff 和快照，关联到对应 Run。

通过条件：新会话不串历史，续接稳定；强度切换在支持时保持历史，不支持就准确报告；取消后能核实运行是否已结束，未知状态阻止冲突执行。

## 8. E4：真实 Goal 控制器

实现需求→规划→冻结→执行→证据→审阅→状态转换。Sol 产出结构化建议；Python 验证引用、版本、代码快照、权限和预算后应用。Review 不直接改 Goal 为完成。

逐项验收使用 PASS/FAIL/BLOCKED/UNKNOWN，必需项有充分证据通过且版本/快照一致才能完成；无效结果、缺失证据或迟到 Review 不自动放行。

在独立演示工作目录做一个小型真实任务，例如实现 `normalize_tags(text)`：按逗号拆分、去首尾空白、忽略空项、去重并保留顺序，用 Python 标准库测试验证。真实路径按实际失败决定是否修复，不为了展示故意增加付费失败轮次；固定失败链由 E2 的模拟场景覆盖。

通过条件：真实 Sol 发起规划，真实 WSL DeepSeek 完成修改/测试，真实 Sol 读取对应证据审阅；整个链由同一个 Python 控制器与浏览器发起。人工手动串接两个 CLI 不能冒充产品闭环。

## 9. E5：工作台主要页面

实现工作目录/会话选择、Goal 创建与启动、计划/逐项验收、双角色输出、Run 状态、暂停/取消/恢复、证据展开、Token 曲线及停止原因。

SSE 使用持久事件游标恢复；临时文字增量可合并，重连后显示最终内容与最新状态，不重发任务。长日志按需展开，截断有补取路径；查询/看板不隐式调用模型。

通过条件：通过实际浏览器操作完成创建与查看，截图或短录屏记录页面；点击重复、刷新页面和断开重连不会额外启动 Run。只证明 API 可调用不等于网页已验收。

## 10. E6：最小 Wiki、Skill 与四种工作流

Wiki 实现当前工作目录标题/摘要/标签/来源索引、正文选读、Markdown 显式导入及作用域记录。未经授权不读跨目录正文，也不能先读正文再决定是否提示。

Skill 实现小型本地 manifest/Registry、项目允许、会话选择、版本冻结和配置/提供/观察调用的区分。只使用项目自建的少量工作流，不批量安装研究中的第三方库。原生发现无法严格隔离时保留阻塞或明确限制，不能仅凭前端过滤宣称隔离完成。

四种工作流提供最小可用版本：Quick Prompt 优化展示原文差异；Goal Review 已进入闭环；手动全链复盘和 Token Audit 读取同一事件/证据产生可追溯报告。记录分析预算，不为普通看板增加自动模型摘要。Deep Optimize、复杂 Profile 和自动效果评分后置。

通过条件：同一个演示 Goal 能被查看、按范围复盘与成本诊断；模拟分析明确标记模拟。已配置/已提供 Skill 不标成已实际调用。

## 11. E7：验收与交付

按下面的 A01–A15 验收，修复实现问题，完成实际可做的浏览器与端到端验证。技术性问题继续处理；只有缺少必要用户输入或外部环境且无独立进展可做时，才以具体阻塞交付。

| ID | 必验行为 | 最少证据 |
| --- | --- | --- |
| A01 | 按说明启动本地网页、正常构建和退出 | 启动/构建命令、退出码、页面证据 |
| A02 | Windows Sol / WSL DeepSeek 实际接入 | 版本、角色/模型、环境与有效原生事件，不含秘密 |
| A03 | 新会话隔离、续接、支持时切强度保留历史 | 不同 Thread/Session、续接前后与能力结果 |
| A04 | 浏览器发起的真实 Goal 完整闭环 | 关联 Goal→Decision→Run→Evidence→Review、代码快照和运行结果 |
| A05 | 模拟失败→重规划→修复→验收 | 确定性场景命令与因果链，标注 simulation |
| A06 | 缺证据/版本或快照不一致不得完成 | 针对错配的行为验证 |
| A07 | 执行预算 100% 阻止下一轮，重启仍锁定，明确恢复 | 准入调用计数、持久状态和恢复事件 |
| A08 | 用量真实/估算/未知分开，重复快照不重复扣量 | 输入与聚合结果、迟到/重置场景 |
| A09 | 重复命令、单目录写入冲突、崩溃恢复不重复执行 | 同幂等键的 Run 数、恢复前后状态 |
| A10 | 暂停/取消只影响所属运行，无不明残留执行 | 取消事件、进程归属和最终状态 |
| A11 | 浏览器刷新/SSE 重连恢复显示不重新启动 | 浏览器操作与服务端 Run 计数 |
| A12 | Skill 版本/范围有效，配置不冒充实际调用 | 两会话可见集合、运行快照、观测状态 |
| A13 | Wiki/Markdown 导入可追溯，跨目录未授权不预读 | 导入来源、作用域及拒绝证据 |
| A14 | 四种轻量工作流可用、复盘/成本引用已有事实 | Prompt 差异、Review、Postmortem、Token Audit 输出 |
| A15 | 本地 API 访问边界与持久数据过滤 | 必要的请求检查及不落原始推理/凭据的验证 |

故障/预算等测试可使用模拟，A02/A04 不能以模拟替代；A03/A10 的原生行为也需实际验证。未能执行的检查写 NOT_RUN，外部依赖缺失写 BLOCKED，测试失败写 FAIL，均不能改成 PASS。

## 12. 完成判定与反馈包

只有必验项通过、真实闭环有证据、已知实现问题得到处理，才报告 `COMPLETE`。外部依赖阻碍真实验证但其余可交付时为 `PARTIAL_BLOCKED`；实现未完成或尚有失败项为 `INCOMPLETE`。不要用测试总数或页面完成掩盖真实执行链未跑通。

输出以下文件，未执行时不预填完成报告：

- `docs/reports/ENVIRONMENT_REPORT.md`：环境与能力。
- `docs/reports/MVP_EXECUTION_REPORT.md`：供本聊天审阅的完整报告，按[模板](../EXECUTION_REPORT_TEMPLATE.md)填写。
- `docs/reports/MVP_EXECUTION_RESULT.json`：机器摘要、A01–A15 状态和证据引用。
- `docs/reports/evidence/`：必要测试输出、浏览器证据和示例 Goal 索引；大日志可留运行目录并给出可访问路径。

更新 README 启动/构建/测试/停止说明、实际状态、MEMORY、WIKI 和索引。当前代码状态用 commit 或文件清单/哈希定位，用户可复现同一验收对象。最终回复只突出完成状态、启动方式、报告路径、真实闭环结果和仍需用户处理的具体项。
