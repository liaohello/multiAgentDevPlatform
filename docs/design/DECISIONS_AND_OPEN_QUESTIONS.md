## 开始实现时应调查 / 由实现提案明确的事项

1. 目标目录是否已有代码、Git、`AGENTS.md`、会话/Goal 数据与前端，如何复用。
2. Windows / WSL 发行版、Python、Codex CLI / App Server 实际版本与可用接口。
3. Sol 与 DeepSeek 的实际提供商、认证方式、模型 ID、续接和推理强度能力。
4. 前端形态与技术栈、是否已有页面。此处没有确定 Qt、Electron、Tauri 或 Web。
5. Windows↔WSL 项目路径映射、工作副本策略、文件权限与进程终止方式。
6. Skill 可发现范围、单轮限制、刷新边界、跨会话隔离与关闭后的历史影响。
7. Token 可实时获得还是结束时结算；未知用量、缓存字段及套餐额度如何表示。
8. 当前轮的收尾/取消策略、运行超时、复核额度、自动重试限制。
9. 默认哪些项目资料可读取、关联提示的索引授权范围、授权的有效期。
10. Goal 中涉及多个执行会话时的映射；初期是否串行以减少状态复杂度。
11. 关键日志的保存/截断规则、恢复时如何确认旧进程是否仍在运行。
12. 第三方 Skill 的真实来源、许可证、脚本行为和兼容性。
13. Ops 的准确来源、Adapter 作用域及运行中撤销策略；`.agent-workspace/` 与 `workspace-data/` 最终统一命名。
14. 历史 JSON 草案的版本字段类型与最终协议、错误摘要及代码快照引用方式。

这些是调查清单，不要求每个事项都先询问用户。可通过只读检查解决的先检查；可逆实现细节在已授权范围内自行选择并记录。

## 本次整理新增的实施澄清

以下是为使方案可落地而补充的工程解释，非用户逐字要求：

- 预算门禁承诺禁止“下一轮”，不能在只有事后计量的情况下承诺零超额。
- Skill 已启用、已提供、实际读取、实际执行、符合规则应分别记录；未知就标记未知。
- 移除后续 Skill 不会擦除既有对话中的内容。
- 接收到通过报告不等于目标已通过；需检查冻结标准与证据。
- 状态名和 JSON 字段是讨论规格，需与实际适配器协商后定版。
