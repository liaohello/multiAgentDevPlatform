# 用量、费用与预算控制

更新：2026-10-15。由原项目整体记忆第 7 节归并；以下保留已明确要求、建议阈值和计量限制的区分。

**已明确：**按会话和 Goal 监控 Token，有依据地估计额度或费用；绿色/红色等状态提示，点击查看随时间与轮次变化的使用曲线。采集和门禁在普通 Python 程序中实现。

用量记录至少区分模型、提供商、输入/输出 Token、缓存等细分项、计量来源、是否估算和采样时间。费用估算保存价格来源、价格日期、币种与计算口径；套餐额度与 API 价格不是同一个概念。无法获知剩余套餐额度时显示未知，不编造精确百分比。

| 执行预算使用率 | 讨论中的展示 / 行为 |
| --- | --- |
| 低于 70% | 绿色，正常运行（阈值为建议） |
| 70%–90% | 预警（阈值为建议） |
| 90%–100% | 红色，允许当前轮按策略运行（阈值为建议） |
| 达到或超过 100% | 禁止自动启动下一执行轮（用户明确要求） |
| 当前轮结束 / 安全中断 | 整理结果，进入待审阅状态 |

建议拆分 `execution_budget` 与 `review_reserve`：前者涵盖日常 Sol 规划、DeepSeek 执行和自动重试；后者只用于终止整理、必要复核与复盘。复核预算不是用户原话中单独明确批准的金额或额度，需在实际配置中定义。

如果用户设定的是 Goal 总预算，100% 规则也必须在总额层生效。执行额度、复核预留和总额之间的关系要显式配置，不能通过拆分账户悄悄扩大用户给定的总上限。

如果复核额度也不足，由 Python 生成事实性终止记录，不能为写总结无限调用模型。复核模型不准借整理任务启动新执行任务。

“达到 100% 禁止下一轮”是调度准入保证，不等于绝对不超总 Token：当前调用可能到结束才返回用量，也可能按收尾策略继续消耗。若要实现绝对上限，还需可用量上限、预算预留与提供商能力支持。对未知用量的准入策略应配置并显式报告。

建议在启动前统一检查 Goal 总额、各提供商/会话限制、预留和未结算调用；并发准入需原子处理，不能让两个 Run 分别看到旧余额后同时通过。未知计量不是零消耗。前端按钮、Sol 文本、Skill 和 WSL 执行结果均不能绕过 Python 门禁。

## Token Audit 与 Ops 的边界

[Token Audit](FOUR_SKILLS_DESIGN.md) 读取程序已采集的事件解释异常，不负责计量、停止或恢复，也不能修改预算。Ops 的指标页面优先由程序聚合现有事件；自动模型 Activity Summary 默认关闭，主动摘要和复盘同样计费、受准入约束。

预算相关 UsageEvent、去重、未结算预留和状态转换见 [数据约定](DATA_CONTRACTS.md)。具体费用来源、模型接口与复核额度仍需在实施时核验，不从历史讨论推定。
